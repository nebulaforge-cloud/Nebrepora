# Nebrepora

A signal board for early tech and open-source breakthroughs. It scores **organic velocity** (1–100), not star counts, for repos, papers, tools, and web products that matter to a game/tech studio.

Live: **https://nebrepora.nebulaforge.dev**

Departments: **Engineering · Game UI/UX · Art · Other engineering**, plus a studio-wide **All** view grouped into department lanes.

## Features

- Department cards and All-view section lanes with counts
- Category, kind, search, and sort filters that work together
- **Run scan** (`s`) adds up to 3 unseen signals matching the scan focus and the current department/category
- **Deep inspect** (`i`) uses cached analysis, falls back gracefully for unknown URLs, keeps a recent-inspections list, and exports markdown
- Shortlist of up to 4 pins, saved in `localStorage`, with a compare table from 2 pins up
- Pulse digest of the top 3 signals by score
- Export (`e`) downloads `nebrepora-briefing.md` and `nebrepora-briefing.json` for the filtered set
- Scoring guide (`?`) and search shortcut (`/`)

## Layout

```
public/            ← the only folder that is deployed
  index.html       page shell; board, FAQ, and SEO blocks are prerendered into it
  data.js          all content: watchlist, scan pool, inspect cache, FAQ, site config
  view.js          pure HTML renderers shared by the browser and the prerender
  app.js           browser wiring (filters, scan, pins, inspect, export, shortcuts)
  styles.css
  robots.txt, sitemap.xml, llms.txt, site.webmanifest, 404.html,
  .well-known/security.txt   ← generated by the prerender
  favicon.*, icon-*.png, apple-touch-icon.png, og-image.png   ← generated by render-assets
scripts/
  prerender.mjs    renders the default board + SEO/AEO/GEO files from data.js
  render-assets.mjs  renders icons + share image with headless Edge/Chrome
  assets/          HTML sources for the icons and share image
docs/              product handbook (not deployed)
```

No framework and no runtime dependencies. Node ≥ 20 is only used at build time.

## Develop

```bash
npm run dev
```

After editing `public/data.js` or `public/view.js`:

```bash
npm run build
```

`npm run check` fails if generated files are stale; CI and the Netlify build both run it. Run `npm run assets` after changing the icon or share-card design.

To change the domain, edit `SITE.url` in `public/data.js`, then rebuild and re-render assets.

## Deploy (Netlify + subdomain)

`netlify.toml` sets the build command, publishes only `public/`, and applies the security headers.

1. **Netlify** → site `nebrepora` → *Site configuration → Build & deploy → Link repository* → GitHub → `nebulaforge-cloud/Nebrepora`, branch `main`. Build settings come from `netlify.toml`.
2. *Domain management → Add a domain* → `nebrepora.nebulaforge.dev` → set it as the **primary domain**. `nebrepora.netlify.app` then 301-redirects to it.
3. **Porkbun** → `nebulaforge.dev` → DNS → add a record: type `CNAME`, host `nebrepora`, answer `nebrepora.netlify.app`, TTL `600`.
4. Back in Netlify: *HTTPS → Verify DNS configuration*. The Let's Encrypt certificate is issued automatically. `.dev` is HSTS-preloaded, so the site loads only once the certificate exists.
5. Keep *Visitor access* public (no SSO or password).

After launch, add the subdomain to Google Search Console and Bing Webmaster Tools and submit `/sitemap.xml`.
